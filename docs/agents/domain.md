# Domain documentation

This repository uses a single domain context. When exploring platform behavior
or changing a design, read [CONTEXT.md](../../CONTEXT.md) and the relevant ADRs
linked from the [GitOps documentation index](../../gitops/docs/README.md).
Repository-wide decisions also live in [docs/adr](../adr).

Use the defined Workload Cell, Workload Cell Profile, Platform Release, and
Release Promotion vocabulary in code discussions, tests, issues, and docs.
When a new concept or decision is accepted, update the glossary or applicable
ADR alongside the implementation. Personal domain-modeling skills are optional;
the checked-in documents are the shared source of truth.

If a proposed change conflicts with an accepted ADR, identify the conflict and
resolve the decision explicitly before treating the new behavior as accepted.
Research and proposals remain non-authoritative until accepted and implemented.
